## 额外发现并修复

- **Zotero 10 当前页接口不兼容**：实际阅读器使用 `_state` 中的视图状态，旧 `_lastViewState` 不再可靠；本页提取改为读取当前焦点视图，覆盖分屏焦点。
- **安装清单约束**：真实 Zotero 10 要求非空 `update_url`，不能为关闭自动更新而删除字段。保留原占位地址，本版仍采用手动升级，没有可用的自动更新服务。
- **异步任务串到另一篇文献**：切换、清空或销毁侧栏后，迟到的图片读取、API 准备和旧中继回调不能提交到新上下文；同文献换 PDF 仍恢复该文献存档。
- **中继永久等待及提供方错配**：自主计时结束无领取或无心跳任务；取消任务不可再被网页领取；已连接站点与下拉选择不一致时明确拒绝发送。
- **ChatGPT 回传和图片发送提示**：按响应流的 append/replace/remove 语义更新，避免重复片段被去重、完整流被旧 DOM 覆盖；统一清理实时和恢复记录中的内部引用标记。禁用按钮本身不算发送成功，已进入生成态后不重复点击成“停止生成”。
- **API 兼容及挂起**：避免重复 `/v1`，识别 Anthropic 端点，兼容非流式 JSON；处理 UTF-8 分块、CRLF、错误帧、异常 EOF、取消和空闲/总超时。
- **MinerU 生命周期**：同附件任务合并、限制并行 GPU 解析；扫描件按总页数处理；缓存校验和迁移读回验证；停用插件后不再启动迟到的任务，运行中的子进程有界终止和清理。

## 两个参考插件的取舍

检查固定源码版本，未把它们的源码直接移植进本项目：

- [llm-for-zotero 的网页发送流程](https://github.com/yilewang/llm-for-zotero/blob/e00afa29446abe55301297163ca889fcf6127aff/src/webchat/pipeline.ts)：准确绑定选中的附件，检查附件状态，处理取消。本项目沿用现有附件标识与上下文代次，重点防止迟到的任务串文献，不引入整套新架构。
- [sync-for-zotero 的附件确认逻辑](https://github.com/yilewang/sync-for-zotero/blob/938fe1b4d918e6706fa10c286b9121facc8bcedf/extension/webchat_shared.js)：将附件“被接收”与“准备完成”分开，并使用投递前基线。本轮借鉴其限定证据范围的思路收紧确认；逐站点上传就绪和提交后附件回执属于后续增强，**本版没有实现同等严格的回执保证**。
- 原仓库许可分别为 [AGPL-3.0](https://github.com/yilewang/llm-for-zotero/blob/e00afa29446abe55301297163ca889fcf6127aff/LICENSE) 与 [Apache-2.0](https://github.com/yilewang/sync-for-zotero/blob/938fe1b4d918e6706fa10c286b9121facc8bcedf/LICENSE)。后续直接移植代码前需要单独评估许可及保留声明，本轮只是学习机制并在现有实现上修复。

以下没有被模拟测试替代，不应标为已通过：

1. 更新 XPI 和油猴脚本后，在日常使用的 ChatGPT、Gemini 登录页面各做三轮连续问答，核对侧栏回传、上下文、中文、引用标记和长公式。

3. 用一篇代表性 PDF 实际运行 MinerU，切换文献继续聊天，返回后确认缓存可用；故障/超时路径已有模拟覆盖，但这不验证本机权重、驱动或特定 PDF 的兼容性。
4. 如果发布时宣传 API 直连，对准备支持的实际端点做一次普通问答、长回答和附件能力检查；本轮没有调用付费模型。
