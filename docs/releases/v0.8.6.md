# 0.8.6 候选：清理失效的长轮询等待请求

状态：本地候选，未提交、推送或发布。配套用户脚本仍为 **1.0.15**，本轮未修改脚本。

## 现场证据

用户确认在更新脚本、重新发送图片、失败后直接获取诊断，期间没有手动刷新。诊断显示已连接，但 `lastTask`、`lastUpload` 和最近心跳均为空；侧栏错误为已领取任务长时间未回传。

1.0.15 的 `executeTask` 会创建 `lastTask`，完成/失败不会清空它。因此当前脚本没有执行这一轮，或报告来自不同/新建的运行实例。不能只凭这份报告认定是正文选择器错误。

提供的 Gemini 结构为 `user-query` 嵌套 `user-query-content`，正文为 `structured-content-container.model-response-text` 嵌套 `message-content`。已按此结构添加测试，当前脚本能读取正文且不重复拼接。诊断里的节点数量不是本轮任务证据。

## 实际复现的丢消息路径

1. 网页已连接，正在等待中继的长轮询回复。
2. 同一页面重新连接，用户脚本取消旧浏览器请求；Zotero 原实现仍保留对应等待对象。
3. 下一条图片任务被交给旧等待对象，标记为已领取。浏览器已取消它，不再执行回调。
4. 当前有效轮询拿不到任务，脚本 `lastTask` 仍为空；Zotero 最后报告长时间未回传。

请求错误后再次轮询也存在同类残留。测试直接连接真实用户脚本和真实中继实现，仅替换 HTTP 传输及外部页面操作；复现断言为“当前页面必须收到领取的任务”，修复前实际得到 `null`。

上述机制与现场报告一致，但无法据此排除重复脚本、其他标签页或页面自行重建；没有取得真实登录页运行实例，仍需安装后现场验收。

## 修复范围

- 同会话重连：释放先前等待请求，但保留已执行任务。
- 新轮询：同一会话只保留最新等待请求，重试不会排在失效请求后面。
- 不重发已执行任务，不自动重复投递图片；不改变超时、提示词或网页选择器。
- 仅改中继逻辑和版本号；不修改日常文献库、存档或浏览器配置。
