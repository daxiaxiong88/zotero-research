# 0.8.8 / 脚本 1.0.18：修补 Gemini 回传开头后超时

本地候选，未推送或发布。需同时安装 XPI 0.8.8 和原位更新油猴脚本 1.0.18，重启 Zotero、刷新 Gemini 后重新发起一问；不必清空原网页对话。旧脚本已经结束并清掉内存的任务不能靠安装新版自动恢复。

## 现场证据

2026-09-10 的 1.0.17 完整诊断：同一个实例领取任务，Gemini DOM 已读取 1738 字符，网络抓取 8 次；09:14:27 出现正文进度，后续 update 直到 09:15:58 才返回。中继已超时，仍返回 `ok:true`，随后心跳的 `complete:true` 让脚本清掉正文。页面完成检查同时出现 `completeControl:false`、`busy:true`、`active:0`、`streaming:false`。

日志时间为 UTC。它证明了正文已经抓到、回调间隔过长、超时后的正文被忽略；并不能单独证明浏览器为何延迟回调。

[Tampermonkey 官方说明](https://www.tampermonkey.net/documentation.php?locale=en&q=GM_xmlhttpRequest)指出 `anonymous:true` 强制 fetch，Chrome 的 fetch 模式不支持请求的原生 `timeout`。旧脚本只设置了该超时参数，缺少独立期限。

## 修补范围

- 请求增加独立期限、取消和单次结算；Worker 与页面计时器互为补充，成功、失败、主动取消均清理计时器，忽略迟到回调。两种计时器都不能突破浏览器的完整冻结。
- 正文回传超时后重试最新文本，不重新粘贴图片或发送问题。诊断记录回传耗时、明确拒绝和网络结束状态。
- 中继可在超时后 20 分钟内补回同一连接、最新已领取任务的正文。部分补回只更新原气泡，不重新锁定侧栏；最终正文到达才清除超时错误。
- 已取消、断开/切换连接、开始下一问、未领取或超过恢复期限的任务不能恢复。已经成功完成的回答不可被较旧的回传覆盖；完全相同的最终回传可以幂等确认。
- Gemini 的正文来源优先级与完成信号分离：页面负责公式结构，网络结束帧作为另一条完成证据。仍需无活动请求、无停止按钮，且正文稳定；没有结束证据时不因短暂静默而宣称完成。
- 保留 0.8.7 普通问答精简和按需取材，不改 API、MinerU、文献库或网页既有历史。
