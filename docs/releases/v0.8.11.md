# 0.8.11 开发候选版 / 网页脚本 1.0.21

## 按使用启动，不再要求单独运行启动器

- Windows 上在侧栏点“打开网页”，或网页未连接时首次发送问题，插件直接调用 Zotero 原生进程接口打开 Chrome，并携带 `--disable-backgrounding-occluded-windows`。
- 不依赖 PowerShell、计划任务、开机启动项、远程调试或额外浏览器配置目录。沿用 Chrome 原有登录；本地已记录同一提供方的对话地址时优先打开该地址。
- 已连接时直接发送到当前对话，不重复打开标签页或抢焦点。API 直连、仅切换文献不启动浏览器。仍需先安装、启用配套 Tampermonkey 脚本。
- Chrome 已经运行时可能只接收新网址而忽略新增启动参数。插件不会关闭窗口或谎称参数已生效；需要时保存工作、从 Chrome 菜单正常退出全部窗口，再从侧栏打开即可。
- 未找到常见安装位置的 Chrome，或非 Windows，使用默认浏览器，不宣称已应用 Chrome 后台参数。

## 长回答捕获与恢复

- 修复 Gemini 未完成帧的二次方扫描：旧实现收不齐外层 JSON 时反复从正文里的 `[` 重扫。约 335 万字符、1000 个方括号的同规模模拟中，单次解析由 34461 ms 降为 86 ms，搜索次数从 1008 降为 2；未完整的数据仍等待后续字节，不误判完成。这是模拟测量，不是用户真实响应的回放。
- XHR 同时读取 `progress`、`readystatechange` 与 `loadend` 的最后数据，避免只有流进度更新时滞留第一句。同一批数据只解析一次。
- 页面恢复或重新可见时立即采样本轮回答并继续回传已有数据；不重复发送问题，不自动截短知识沉淀历史，不把静默或恢复事件当作回答完成。
- 诊断新增实际 `freeze/resume/visibilitychange` 事件、心跳调度延迟和解析耗时，仍只保存结构、时序和字符数。本轮时间线独立保留，不会被完成后的空闲轮询覆盖。

## 验证边界

自动启动、会话复用、并发打开、切换文献及启动失败的回归通过后才打包。浏览器窗口被完全遮挡时的真实长知识沉淀仍需用户复测。受控测试验证长流进度和真实冻结后的恢复，**不代表脚本能在浏览器完全冻结时执行**。本候选版未修改浏览器全局节能设置，也没有继续堆叠全局禁用参数。

本地验证：252 项 JavaScript 测试、98 项 Python 测试通过（2 项因 Windows 符号链接权限跳过）；Chromium 11 项、Firefox 12 项集成测试通过。独立 Chrome 的真实冻结/恢复测试通过。Zotero 10.0.2 隔离配置内的原生检查通过，浏览器启动边界被测试拦截，不操作用户现有浏览器。XPI SHA-256：`56cae6614d7ce91b4617dc31a6317b2fd40f9b951e274ab937da19a02f711003`。

更新 XPI 和油猴脚本后刷新原 AI 标签页即可，不需要清空原有对话。若仍在知识沉淀时卡住，请在故障后下载新版完整诊断 JSON；这次重点查看 `lifecycle`、`lastTask.heartbeatSchedulingDelayMs`、`lastTask.lastUpdate`。
