# 0.6.3 存档与蒸馏预算

本次只改存档和消息组装；保留网页连接、API 配置、选文、截图和现有操作方式。不新增设置页、不自动回收孤立存档、不自动增加模型调用。

## 存档如何变化

仍使用配置目录 `zotero-research-sessions/` 下每篇文献一个 JSON。文件增加 `format: 2`，消息结构继续兼容 0.6.2：

- 用户问题和 AI 回答不做摘要或截断；仍沿用每篇最多 500 条消息的滚动规则。
- `sourceContext` 保存供追问使用的原文及材料范围，沿用约 24,000 字符的上限。
- `evidence` 只保存标识、页码、序号、前 200 字符和截断标记，避免再次完整存储同一份原文。
- 老档没有 `sourceContext` 时，先从对应回答的完整证据恢复，再精简证据字段。
- 范围提示 `contextNotice` 与知识沉淀标志一起保存；恢复后仍可看到本次回答覆盖了多少记录。

正常打开旧档只读，不立即改写，也不会扫描、批量迁移其他文献。首次重新保存旧格式文件之前，保留同目录的 `{itemKey}.json.pre-v2.bak`。这份首次迁移备份不被后续保存覆盖；备份创建或校验失败时停止替换主档。它保留旧文件的原始文本，不重新序列化旧 JSON。

保留备份意味着首次转换后，这一篇文献会长期多占一份旧档的空间，直到清空该文献的记录才会一并删除；它不是每轮一份的无限备份，也不是所有历史的永久保管库。后续正常写入仍保留最多 500 条消息。长问答和大量原文仍会占空间，瘦身并不意味着文件永远只有几 KB。

## 写盘与清空

每篇文献有独立的顺序队列，读取、保存、清空按先后执行。一次写入已经开始时允许完成；它后面的连续待写快照可以合并为最新一份。清空是顺序屏障，不能被待写合并抹掉。

- 保存 A → 清空：最终不存在本篇主档。
- 保存 A → 清空 → 保存 B：最终只保留清空后的 B。
- 清空 → 读取：不会读到清空前的文件。
- 停用插件：停止接收新操作，等待已排队的操作完成。

清空按钮会同时删除**这一篇文献**的主档和首次迁移备份；不会删除其他文献，也不删除浏览器里的对话。存档恢复期间暂缓新提问，避免用新对话覆盖尚未读出的旧记录。保存或清空失败会明确提示。

继续使用 Zotero 原有文件写入方法：本机 Zotero 的 `Zotero.File.putContentsAsync()` 对字符串使用 `OS.File.writeAtomic()` 和同路径 `.tmp` 文件。串行队列也避免同一目标的临时文件并发冲突；不直接访问文献库数据库。

## 预算与知识沉淀

普通 API 问答最多取最近 11 轮，知识沉淀最多 250 轮。顺序如下：

1. 计算本轮指令和材料，再加入完整的历史问答。
2. 超预算时先缩减历史辅助原文，保持问答内容完整。
3. 仍超预算才移除较早的完整问答；模型和侧栏都显示覆盖范围。
4. 在实际序列化后再次核对文本长度，包括范围提示和分隔文字。
5. 如果蒸馏一轮也装不下，停止请求并提示“单轮对话过长，请分段沉淀”；存档不因本次预算裁剪而改变。

API 文本上限为 150,000 字符，网页蒸馏最终文本上限为 60,000 字符。这里的长度是 JavaScript 字符串长度，不是模型 token 数；不包含 PDF、图片的上下文消耗，不能保证适配所有模型的上下文窗口。

网页蒸馏继续携带本地已记录的问答，换新网页对话不必然失去沉淀材料。但只在网页发生、未回传侧栏的交流，以及先前上传的文件内容，并不因此自动进入本地存档。

## 升级与回滚

安装 `dist/zotero-research-0.6.3.xpi`；这次的改动不要求更新油猴脚本。构建脚本在写新包之前，会把 `dist` 里已存在的最新安装包复制为 `zotero-research-previous-stable.xpi`（连同 `.sha256`、`.manifest.json`），作为上一份可回滚的发布包；不要手工重新打包覆盖它。

新文件保留旧版能识别的 `messages`、`content`、`sourceContext`、`evidence` 等字段，所以回退 XPI 后仍可读取问答。新版本能继续读取旧版随后保存的记录；首次迁移备份仍只保留最早那一份。通常回退插件即可，不应顺手用旧备份覆盖当前记录，否则会丢掉备份之后的新问答。

若确实需要恢复首次迁移前的文件，应先完全退出 Zotero，并另存当前主档，再恢复对应 `.pre-v2.bak`；不要在 Zotero 运行时替换存档。本轮没有自动安装插件或改写实际存档。

## 验证范围

测试使用模拟文件系统和模型适配器，覆盖旧档恢复、证据去重、首次备份、顺序读写、清空屏障、写盘失败恢复、停止时排空队列、超长单轮和最终文本预算。500 条消息的合成样例比较瘦身前后的 UTF-8 字节数；不是对用户真实文件的改写或实测压缩率。
